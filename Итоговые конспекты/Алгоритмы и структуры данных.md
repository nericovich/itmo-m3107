# 1. Оценка сложности алгоритмов

## Основные понятия

**Качество кода vs качество алгоритма.**

* **Качество кода (читабельность / оформление)** влияет на команду и поддержку: если код сложный, неструктурированный и написан сплошным полотном («спагетти-код»), в нём тяжело искать ошибки и дорабатывать. *Пользователь код не видит*, но видит результат его работы.
* **Качество алгоритма (производительность):**
  * **медленная работа** — пользователи уходят, бизнес теряет деньги; мобильные устройства и рабочие машины часто ограничены по ресурсам;
  * **чрезмерное потребление памяти** — нехватка RAM для других процессов, замедление системы, невозможность обрабатывать большие объёмы данных.

## Определения

Сложность измеряется как функция от размера входных данных $n$:
* $M(n)$ — сложность по **памяти** (Memory);
* $T(n)$ — сложность по **времени** (Time).

**Правила подсчёта памяти $M(n)$:**
* $1$ примитивная переменная = $1$ пункт сложности;
* массив / строка размера $n$ = $n$ пунктов.

**Правила подсчёта времени $T(n)$:**
* $1$ базовая операция (присваивание, сравнение, арифметическое действие) = $1$ пункт;
* цикл из $n$ итераций по $k$ операций = $k \cdot n$ пунктов;
* условие (`if`) с $t$ операциями (логические проверки + действия) = $t$ пунктов.

## Примеры

### Пример 1. Циклы и условия

```c
int i, j, n = 100;              // M: +3; T: +1 (присваивание n)
int A[n] = 1;                   // M: +n; T: +n (инициализация)
char B[n];                      // M: +n

for i = 1 to n do               // T: +1 (старт цикла)
    j++;                        // T: +n (1 операция * n итераций)

i = n;                          // T: +1
while (A[i] + A[i-1] > 0) {     // T: условие (3 оп.)
    A[i + 1] = A[i];            // T: 2 оп.
    i = i - 1;                  // T: 2 оп.
    if (i < 0 && (i/2 == 0))    // T: 4 оп. (проверки)
        then j = n;             // T: 1 оп.
}                               // Итого в теле while: 3 + 2 + 2 + 5 = 12 оп. на итерацию
```

* **Память:** $M(n) = 3 + n + n = 2n + 3$.
* **Время:** $T(n) = 1 + n + 1 + n + 1 + 12n = 14n + 2$.

### Пример 2. Зависимый вложенный цикл (арифметическая прогрессия)

```c
for i = 1 to n do
    for j = 1 to i do
        A[i] = A[i] + A[j];
```

Внутренний цикл зависит от шага внешнего: при $i = 1$ — 1 шаг, при $i = 2$ — 2 шага, …, при $i = n$ — $n$ шагов. Общее число итераций — сумма арифметической прогрессии:

$$T(n) = \frac{1 + n}{2} \cdot n = \frac{n^2 + n}{2}$$

### Пример 3. Зависимость от входных данных (лучший и худший случаи)

```c
i = N;
while (A[i] + A[i-1] > N) {
    A[i - 1] = A[i];
    i = i - 1;
}
```

* **Лучший случай (минимум):** условие сразу ложно — цикл не выполняется ни разу (3 операции на проверку условия).
* **Худший случай (максимум):** цикл выполняется $N$ раз — $\approx 7N$ операций.

# 2. Асимптотический анализ

## Основные понятия

При росте $n$ константы и младшие слагаемые теряют значимость, поэтому анализируется **порядок роста** функции.

## Определения

| Нотация | Название | Определение | Смысл |
| :--- | :--- | :--- | :--- |
| $O(g(n))$ | «О» большое (Big-O) | $\exists c > 0,\ n_0 > 0 : \forall n > n_0 \implies 0 \le f(n) \le c \cdot g(n)$ | **оценка сверху** (худший случай) |
| $\Omega(g(n))$ | Омега (Big-Omega) | $\exists c > 0,\ n_0 > 0 : \forall n > n_0 \implies 0 \le c \cdot g(n) \le f(n)$ | **оценка снизу** (лучший случай) |
| $\Theta(g(n))$ | Тета (Big-Theta) | $\exists c_1, c_2 > 0,\ n_0 > 0 : \forall n > n_0 \implies 0 \le c_2 g(n) \le f(n) \le c_1 g(n)$ | **точная оценка** (сверху и снизу) |

> **[Дополнение]** Строго говоря, $O$ и $\Omega$ — это оценки сверху и снизу для *функции*; связь с «худшим/лучшим случаем», указанная в таблице, — распространённое упрощение из лекции: чаще всего $O$ применяют к времени работы в худшем случае.

## Теоремы и свойства

**Теорема о связи:**
$$f(n) = \Theta(g(n)) \iff f(n) = O(g(n)) \ \text{и}\ f(n) = \Omega(g(n))$$

**Свойства $O$-нотации.** Пусть $T_1(n) = O(g_1(n))$, $T_2(n) = O(g_2(n))$, $C$ — константа.

1. **Сумма:** $T_1(n) + T_2(n) = O(\max(g_1(n), g_2(n)))$ — выбирается старший порядок роста.
2. **Произведение:** $T_1(n) \cdot T_2(n) = O(g_1(n) \cdot g_2(n))$.
3. **Умножение на константу:** $C \cdot T_1(n) = O(g_1(n))$ — константа отбрасывается.
4. **Сложение с константой:** $T_1(n) + C = O(g_1(n))$ — константа отбрасывается.

## Примеры упрощения

* $T(n) = 2n^2 + 2n + 3 \implies O(n^2)$
* $T(n) = 1290n^3 + 12n^2 - 3586 \implies O(n^3)$
* $T(n) = 2n^2 \log n + 142n^2 - n \implies O(n^2 \log n)$
* $T(n) = 1290n^3 + 2n^2 \log n - 142n^2 - n + 386 \implies O(n^3)$

## Зачем оценивать алгоритмы на практике

Сравнение двух подходов при $N = 10^7$ элементов:

* **Устройство 1 (мощный сервер):** $10^9$ оп./сек, алгоритм $O(n^2)$:
  $$\text{Время} = \frac{10^7 \cdot 10^7}{10^9} = 10^5 \text{ сек} \approx 27{,}7 \text{ часов} \ (> \text{суток})$$
* **Устройство 2 (слабый смартфон):** $10^7$ оп./сек, алгоритм $O(n \log_2 n)$:
  $$\text{Время} = \frac{10^7 \cdot \log_2(10^7)}{10^7} \approx 23{,}25 \text{ сек} \ (< \text{минуты})$$

> **Вывод:** эффективный алгоритм на слабом оборудовании побеждает неэффективный алгоритм на мощном суперкомпьютере.

## Классификация сложностей

```
O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)
[---------------- ОТЛИЧНО ----------------]   [---- ПЛОХО ----]   [-- КАТАСТРОФА --]
```

1. **Константная — $O(1)$:** доступ к элементу массива по индексу, базовые арифметические действия.
2. **Логарифмическая — $O(\log n)$:** область поиска на каждом шаге делится на константу (например, пополам). *Пример:* бинарный поиск (`binSearch`).
3. **Линейная — $O(n)$:** однократный проход по входным данным. *Пример:* поиск элемента / подсчёт совпадений в массиве.
4. **Линеарифметическая — $O(n \log n)$:** разделение задачи пополам ($\log n$) и объединение результатов проходом по всем элементам ($n$). *Пример:* Merge Sort, Quick Sort (в среднем).
5. **Квадратичная — $O(n^2)$:** вложенные циклы, обработка всех пар элементов. *Пример:* Bubble Sort.
6. **Кубическая — $O(n^3)$:** тройные вложенные циклы. *Пример:* перебор всех троек чисел, базовое умножение матриц.
7. **Экспоненциальная — $O(2^n)$ / $O(a^n)$:** перебор всех подмножеств/комбинаций. *Пример:* перебор всех комбинаций занятых мест.
8. **Факториальная — $O(n!)$:** перебор всех перестановок. *Пример:* перестановки людей на $n$ местах, задача коммивояжёра (полный перебор).

## Практический ориентир применимости

| Сложность | Макс. рабочий $n$ (лимит $\approx 1$ сек) | Вердикт |
| :--- | :--- | :--- |
| $O(1)$ / $O(\log n)$ | практически любые ($> 10^9$) | работает всегда и моментально |
| $O(n)$ | $\approx 10^7 - 10^8$ | отлично для потоковой обработки |
| $O(n \log n)$ | $\approx 10^6 - 5 \cdot 10^7$ | стандарт для эффективных сортировок |
| $O(n^2)$ | $\approx 10^4$ | терпимо только для небольших данных |
| $O(n^3)$ | $\approx 500$ | требует оптимизации |
| $O(2^n)$ | $\approx 20 - 26$ | очень медленно (экспоненциальный взрыв) |
| $O(n!)$ | $\approx 10 - 11$ | неприменимо для реальных объёмов |

# 3. Корректность алгоритмов: инвариант цикла

## Определения

**Инвариант цикла (Loop Invariant)** — логическое утверждение о состоянии данных, истинное перед началом каждой итерации цикла и после её завершения.

## Методы: структура доказательства корректности

1. **Инициализация (Initialization):** утверждение истинно перед первой итерацией.
2. **Сохранение (Maintenance):** если утверждение истинно перед шагом $k$, оно остаётся истинным перед шагом $k+1$.
3. **Завершение (Termination):** при выходе из цикла утверждение гарантирует, что алгоритм решил задачу.

## Пример: корректность сортировки вставками

* **Инвариант:** перед началом каждой итерации внешнего цикла по $j$ подмассив $A[0 \dots j-1]$ состоит из тех же элементов, что изначально находились в $A[0 \dots j-1]$, но расположенных по возрастанию.
* **Инициализация:** при $j = 1$ подмассив $A[0 \dots 0]$ состоит из одного элемента и заведомо отсортирован.
* **Сохранение:** внутренний цикл сдвигает все элементы $A[i] > key$ (т. е. $A[j-1], A[j-2], \dots$) вправо и ставит `key` на позицию, где $A[i] \le key$. Подмассив $A[0 \dots j]$ становится отсортированным.
* **Завершение:** цикл завершается при $j = n$; подмассив $A[0 \dots n-1]$ отсортирован $\implies$ весь массив упорядочен.

# 4. Устойчивость сортировок и многокритериальная сортировка

## Определения

**Устойчивая (стабильная) сортировка** — алгоритм, сохраняющий исходный относительный порядок элементов с одинаковыми значениями ключа.

* Исходный массив: $[3_a, 1, 3_b]$
* **Устойчивая:** $[1, 3_a, 3_b]$ (порядок $3_a$ и $3_b$ сохранён)
* **Неустойчивая:** $[1, 3_b, 3_a]$ (порядок нарушен)

## Основные понятия: сортировка составных объектов

На практике сортируют не примитивные числа, а **составные сущности** (записи/структуры) по одному или комбинации критериев.

**Python:**
```python
from dataclasses import dataclass

@dataclass
class Student:
    name: str        # ФИО
    course: int      # Курс (1..4)
    group: str       # Номер группы (напр. "M3101")
    age: int         # Возраст
    code_isu: int    # Номер ИСУ
```

**C++:**
```cpp
#include <string>

struct Student {
    std::string name; // ФИО
    int course;       // Курс (1..4)
    std::string group;// Номер группы (напр. "M3101")
    int age;          // Возраст
    int code_isu;     // Номер ИСУ
};
```

## Методы

### Способ 1. Составной ключ / компаратор

Задача: отобрать первокурсников групп M3101 и M3102 и упорядочить их **по группе**, а внутри группы — **по алфавиту**.

**Python:**
```python
students = [
    Student("Иванов И.", 1, "M3101", 18, 123456),
    Student("Петров П.", 1, "M3102", 19, 123457),
    Student("Алексеев А.", 1, "M3101", 18, 123458),
]

# 1. Фильтрация (1 курс, группы M3101 и M3102)
filtered = [
    s for s in students
    if s.course == 1 and s.group in {"M3101", "M3102"}
]

# 2. Многокритериальная сортировка:
# первичный ключ — группа, вторичный — имя по алфавиту
filtered.sort(key=lambda s: (s.group, s.name))
```

**C++:**
```cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>
#include <set>

int main() {
    std::vector<Student> students = {
        {"Иванов И.", 1, "M3101", 18, 123456},
        {"Петров П.", 1, "M3102", 19, 123457},
        {"Алексеев А.", 1, "M3101", 18, 123458}
    };

    // 1. Фильтрация
    std::set<std::string> target_groups = {"M3101", "M3102"};
    std::vector<Student> filtered;
    for (const auto& s : students) {
        if (s.course == 1 && target_groups.count(s.group)) {
            filtered.push_back(s);
        }
    }

    // 2. Многокритериальная сортировка через лямбда-компаратор
    std::sort(filtered.begin(), filtered.end(), [](const Student& a, const Student& b) {
        if (a.group != b.group) {
            return a.group < b.group; // Сначала по группе
        }
        return a.name < b.name;       // Затем по алфавиту
    });
}
```

### Способ 2. Многостадийная сортировка устойчивым алгоритмом

Если отсортировать список сначала по **вторичному** ключу, а затем **устойчивой** сортировкой по **первичному** — данные окажутся упорядочены по обоим критериям.

**Python:**
```python
@dataclass
class Item:
    group: str
    score: int

items = [
    Item("M3101", 59),
    Item("M3102", 58),
    Item("M3101", 85),
    Item("M3102", 70)
]

# Шаг 1: сортируем по баллу (по убыванию)
items.sort(key=lambda x: x.score, reverse=True)

# Шаг 2: стабильно сортируем по группе
# list.sort() в Python гарантированно устойчив (Timsort)
items.sort(key=lambda x: x.group)

# Результат: внутри каждой группы баллы остаются отсортированы по убыванию
# -> Item('M3101', 85), Item('M3101', 59), Item('M3102', 70), Item('M3102', 58)
```

**C++:**
```cpp
#include <iostream>
#include <vector>
#include <string>
#include <algorithm>

struct Item {
    std::string group;
    int score;
};

int main() {
    std::vector<Item> items = {
        {"M3101", 59}, {"M3102", 58}, {"M3101", 85}, {"M3102", 70}
    };

    // Шаг 1: сортируем по баллу (по убыванию)
    std::stable_sort(items.begin(), items.end(), [](const Item& a, const Item& b) {
        return a.score > b.score;
    });

    // Шаг 2: устойчиво сортируем по группе
    std::stable_sort(items.begin(), items.end(), [](const Item& a, const Item& b) {
        return a.group < b.group;
    });
    // Внутри групп порядок по баллам сохранился
}
```

## Условия устойчивости рассмотренных алгоритмов

* **Insertion Sort** — устойчив, если условие сдвига строгое: `arr[i] > key` (равный элемент не двигается левее своих дубликатов). При `arr[i] >= key` — **неустойчив**.
* **Merge Sort** — устойчив, если при равенстве берётся элемент из левой половины: `arr[left + it1] <= arr[mid + it2]`. При `<` — **неустойчив**.
* **Bubble Sort** — устойчив (соседние равные элементы не меняются местами).
* **Selection Sort** — неустойчив в стандартной реализации (далёкий `swap` может переместить элемент через равные ему).
* **QuickSort** — неустойчив (в процессе перестановок относительный порядок равных ключей не сохраняется).
* **HeapSort** — неустойчив (из-за «далёких» обменов корня с последним элементом и просеивания).

# 5. Простые сортировки за O(n²)

## 5.1. Сортировка вставками (Insertion Sort)

### Идея

Массив делится на две части:
1. **Отсортированная часть** — изначально один элемент `A[0]` (один элемент всегда упорядочен).
2. **Неотсортированная часть** — элементы `A[1] … A[n-1]`.

На каждом шаге $j$ (начиная с $j = 1$) элемент `key = A[j]` вставляется на подходящее место в отсортированную левую часть.

### Оптимизация: сдвиги (shift) вместо обменов (swap)

* **Наивный вариант (`swap`):** поэлементно меняем текущий элемент с предыдущим, пока он меньше. Каждый `swap` — 3 присваивания, при сдвиге на $k$ позиций — $3k$ операций.
* **Оптимальный вариант (сдвиг):**
  1. сохраняем вставляемый элемент: `key = A[j]`;
  2. сдвигаем элементы, строго большие `key`, вправо: `A[i + 1] = A[i]`;
  3. в освободившуюся позицию один раз записываем `key`: `A[i + 1] = key`.
  * *Выигрыш:* вместо $3k$ операций записи — $k + 2$ (примерно в 3 раза меньше).

### Реализация

**Python:**
```python
def insertion_sort(arr: list[int]) -> None:
    n = len(arr)
    for j in range(1, n):
        key = arr[j]
        i = j - 1
        # Ищем место для key, сдвигая большие элементы вправо
        while i >= 0 and arr[i] > key:
            arr[i + 1] = arr[i]
            i -= 1
        arr[i + 1] = key

# data = [7, 4, 1, 3, 2, 5, 2, 8, 11]
# insertion_sort(data)  ->  [1, 2, 2, 3, 4, 5, 7, 8, 11]
```

**C++:**
```cpp
#include <vector>

void insertionSort(std::vector<int>& arr) {
    int n = arr.size();
    for (int j = 1; j < n; ++j) {
        int key = arr[j];      // Сохраняем вставляемый элемент
        int i = j - 1;         // Граница отсортированной части
        // Сдвигаем элементы, которые больше key, вправо
        while (i >= 0 && arr[i] > key) {
            arr[i + 1] = arr[i];
            --i;
        }
        arr[i + 1] = key;      // Вставляем key на нужную позицию
    }
}
```

Корректность — см. [раздел 3](#3-корректность-алгоритмов-инвариант-цикла).

### Сложность и свойства

* **Лучший случай:** $O(n)$ — массив уже отсортирован, условие `arr[i] > key` ложно сразу, внутренний `while` не делает итераций.
* **Средний случай:** $O(n^2)$ — каждый элемент смещается в среднем на половину отсортированной части (с меньшей константой благодаря эффективным сдвигам).
* **Худший случай:** $O(n^2)$ — массив отсортирован в обратном порядке:
  $$T(n) = \sum_{j=1}^{n-1} j = \frac{n(n-1)}{2} = O(n^2)$$
* **Память:** $O(1)$ — сортировка на месте (*in-place*), переменные `key`, `i`, `j`.
* **Устойчивость:** да (при строгом условии `>`).

## 5.2. Сортировка выбором (Selection Sort)

### Идея

* В неотсортированном подмассиве от `i` до `n-1` находится минимальный элемент.
* Найденный минимум меняется местами с первым неотсортированным элементом `A[i]`.
* Индекс `i` увеличивается, процесс повторяется.

### Реализация (C++)

```cpp
#include <vector>
#include <algorithm>

void selectionSort(std::vector<int>& A) {
    int n = A.size();
    for (int i = 0; i < n - 1; i++) {
        int minIndex = i; // Предполагаем, что текущий элемент минимальный

        // Ищем индекс минимального элемента в оставшейся части
        for (int j = i + 1; j < n; j++) {
            if (A[j] < A[minIndex]) {
                minIndex = j;
            }
        }

        // Меняем местами найденный минимум с A[i]
        if (minIndex != i) {
            std::swap(A[i], A[minIndex]);
        }
    }
}
```

### Сложность и свойства

* **Время (любой случай):** $O(n^2)$. Число сравнений всегда равно $\frac{n(n-1)}{2}$ независимо от исходной упорядоченности.
* **Число обменов:** $O(n)$ (не более $n-1$) — полезно, когда запись в память дорогая.
* **Память:** $O(1)$.
* **Устойчивость:** нет (в стандартной реализации).
* **Связь с HeapSort:** поиск минимума за $O(n)$ на каждом из $n$ шагов даёт $O(n^2)$. Если заменить линейный поиск на извлечение из двоичной кучи — получится **HeapSort** за $O(n \log n)$ (см. [раздел 9](#9-двоичная-куча-и-пирамидальная-сортировка-heapsort)).

## 5.3. Пузырьковая сортировка (Bubble Sort)

### Идея

* Последовательные проходы по массиву со сравнением соседних элементов `A[j]` и `A[j+1]`.
* Если `A[j] > A[j+1]`, они меняются местами. За один проход наибольший элемент неотсортированной части «всплывает» в конец.
* **Оптимизация флагом `swapped`:** если за проход не было ни одного обмена, массив уже отсортирован — алгоритм завершается досрочно.

### Реализация (C++)

```cpp
#include <vector>
#include <algorithm>

void bubbleSort(std::vector<int>& A) {
    int n = A.size();
    for (int i = 0; i < n - 1; i++) {
        bool swapped = false; // Флаг наличия обменов

        for (int j = 0; j < n - i - 1; j++) {
            if (A[j] > A[j + 1]) {
                std::swap(A[j], A[j + 1]);
                swapped = true;
            }
        }

        // Если обменов не было, массив отсортирован
        if (!swapped) {
            break;
        }
    }
}
```

### Сложность и свойства

* **Худший случай:** $O(n^2)$ (массив в обратном порядке); **средний:** $O(n^2)$.
* **Лучший случай:** $O(n)$ — с флагом `swapped` на отсортированном массиве: $n-1$ сравнений и 0 обменов.
* **Память:** $O(1)$. **Устойчивость:** да.

## Выводы по простым сортировкам

1. **Вставки** — наиболее эффективна из элементарных на частично отсортированных данных и небольших массивах ($O(n)$ в лучшем случае).
2. **Выбор** минимизирует число записей в память ($O(n)$ обменов), но делает $O(n^2)$ сравнений всегда.
3. **Пузырёк** с флагом `swapped` может завершиться за $O(n)$, но обычно уступает вставкам из-за частых `swap`.

# 6. Парадигма «Разделяй и властвуй»

## Методы

Метод декомпозиции (Divide and Conquer) состоит из трёх шагов:
1. **Разделение (Divide):** дробление задачи на несколько меньших подзадач того же типа.
2. **Властвование (Conquer):** рекурсивное решение подзадач; если размер задачи минимален (базовый случай) — решаем напрямую.
3. **Комбинирование (Combine):** сборка общего решения из решений подзадач.

## Пример: рекурсивная сумма массива

**Python:**
```python
def recursive_sum(arr: list[int], left: int, right: int) -> int:
    # Базовый случай: подмассив из 1 элемента
    if left == right:
        return arr[left]

    mid = (left + right) // 2                        # 1. Divide
    left_sum = recursive_sum(arr, left, mid)         # 2. Conquer
    right_sum = recursive_sum(arr, mid + 1, right)
    return left_sum + right_sum                      # 3. Combine

# arr = [4, 5, 1, 9, 13, 11, 7]
# recursive_sum(arr, 0, len(arr) - 1)  ->  50
```

**C++:**
```cpp
#include <vector>

int recursiveSum(const std::vector<int>& arr, int left, int right) {
    if (left == right) {                  // Базовый случай: 1 элемент
        return arr[left];
    }
    int mid = left + (right - left) / 2;  // 1. Divide
    int left_sum = recursiveSum(arr, left, mid);       // 2. Conquer
    int right_sum = recursiveSum(arr, mid + 1, right);
    return left_sum + right_sum;          // 3. Combine
}
```

На этой парадигме основаны Merge Sort ([раздел 7](#7-сортировка-слиянием-merge-sort)) и QuickSort ([раздел 8](#8-быстрая-сортировка-quicksort)).

# 7. Сортировка слиянием (Merge Sort)

## Методы и алгоритмы

* **Divide:** делим полуинтервал $[left, right)$ пополам: $mid = \lfloor (left + right) / 2 \rfloor$.
* **Conquer:** рекурсивно сортируем $[left, mid)$ и $[mid, right)$. Базовый случай: $left + 1 \ge right$ (0 или 1 элемент).
* **Combine (`merge`):** сливаем две отсортированные части двумя указателями во вспомогательный массив. Когда одна часть закончилась, остаток другой дописывается («доливается хвост»).

**Python:**
```python
def merge(arr: list[int], left: int, mid: int, right: int) -> None:
    it1 = 0  # указатель для левой части [left, mid)
    it2 = 0  # указатель для правой части [mid, right)
    result = []

    while left + it1 < mid and mid + it2 < right:
        # Условие <= обеспечивает устойчивость алгоритма
        if arr[left + it1] <= arr[mid + it2]:
            result.append(arr[left + it1])
            it1 += 1
        else:
            result.append(arr[mid + it2])
            it2 += 1

    while left + it1 < mid:          # доливаем левый хвост
        result.append(arr[left + it1])
        it1 += 1

    while mid + it2 < right:         # доливаем правый хвост
        result.append(arr[mid + it2])
        it2 += 1

    for i, val in enumerate(result): # копируем результат обратно
        arr[left + i] = val


def merge_sort(arr: list[int], left: int, right: int) -> None:
    if left + 1 >= right:            # отрезок из 0 или 1 элемента
        return
    mid = (left + right) // 2
    merge_sort(arr, left, mid)
    merge_sort(arr, mid, right)
    merge(arr, left, mid, right)
```

**C++:**
```cpp
#include <vector>

void merge(std::vector<int>& arr, int left, int mid, int right) {
    int it1 = 0; // указатель для левой части [left, mid)
    int it2 = 0; // указатель для правой части [mid, right)
    int len = right - left;
    std::vector<int> result(len);

    while (left + it1 < mid && mid + it2 < right) {
        // Условие <= обеспечивает устойчивость
        if (arr[left + it1] <= arr[mid + it2]) {
            result[it1 + it2] = arr[left + it1];
            it1++;
        } else {
            result[it1 + it2] = arr[mid + it2];
            it2++;
        }
    }
    while (left + it1 < mid) {       // доливаем левый хвост
        result[it1 + it2] = arr[left + it1];
        it1++;
    }
    while (mid + it2 < right) {      // доливаем правый хвост
        result[it1 + it2] = arr[mid + it2];
        it2++;
    }
    for (int i = 0; i < len; ++i) {  // копируем обратно
        arr[left + i] = result[i];
    }
}

void mergeSort(std::vector<int>& arr, int left, int right) {
    if (left + 1 >= right) {         // отрезок длины <= 1
        return;
    }
    int mid = left + (right - left) / 2;
    mergeSort(arr, left, mid);
    mergeSort(arr, mid, right);
    merge(arr, left, mid, right);
}
```

## Формулы: вывод сложности

**Время.** Рекуррентное уравнение:
$$T(n) = \begin{cases} O(1), & n = 1 \\ 2T(n/2) + O(n), & n > 1 \end{cases}$$

Развёртка по уровням:
$$\begin{aligned}
T(n) &= 2T(n/2) + O(n) \\
&= 4T(n/4) + 2O(n/2) + O(n) = 4T(n/4) + 2O(n) \\
&= 2^k T\left(\frac{n}{2^k}\right) + k \cdot O(n)
\end{aligned}$$

При $2^k = n \implies k = \log_2 n$:
$$T(n) = n \cdot T(1) + \log_2 n \cdot O(n) = O(n \log n)$$

Сложность $O(n \log n)$ одинакова в лучшем, среднем и худшем случаях.

**Память:**
* вспомогательный массив для слияния — $O(n)$;
* стек рекурсии (глубина дерева) — $O(\log n)$;
* итого $M(n) = O(n) + O(\log n) = O(n)$.

**Устойчивость:** да (при `<=` в `merge`).

# 8. Быстрая сортировка (QuickSort)

## Основные понятия

* **Стратегия:** «разделяй и властвуй».
* **Базовый случай:** одноэлементный массив всегда отсортирован — условие выхода из рекурсии.
* **Рекурсивный процесс:** на спуске рекурсии происходит разбиение массива (**Partition**) и рекурсивные запуски для подмассивов, на возврате — массив уже собран отсортированным.
* **Ключевой этап — Partition:** изменяет порядок элементов в подмассиве `a[l...r]` без использования дополнительной памяти.

## Методы и алгоритмы: схема разбиения Ломуто

Опорный элемент (**pivot**) — самый правый элемент подмассива `a[r]`.

```cpp
#include <algorithm>

// Разбиение подмассива a[l...r] по схеме Ломуто
int partition(int a[], int l, int r) {
    int pivot = a[r];    // опорный элемент
    int i = l - 1;       // граница элементов, меньших или равных опорному

    for (int j = l; j < r; j++) {
        if (a[j] <= pivot) {        // элемент <= опорного
            i = i + 1;              // увеличиваем границу
            std::swap(a[i], a[j]);  // помещаем элемент в блок меньших
        }
    }
    std::swap(a[i + 1], a[r]);      // ставим pivot на итоговую позицию i + 1
    return i + 1;                   // индекс опорного элемента
}

void quicksort(int a[], int l, int r) {
    if (l < r) {                    // условие выхода из рекурсии
        int q = partition(a, l, r);
        quicksort(a, l, q - 1);     // левая часть
        quicksort(a, q + 1, r);     // правая часть
    }
}
```

**Пояснение работы Partition:**
1. Переменная `i` — текущая граница элементов, меньших либо равных `pivot`.
2. Индекс `j` проходит по подмассиву и проверяет `a[j] <= pivot`.
3. После цикла `pivot` меняется местами с `a[i + 1]` и оказывается ровно между меньшими (слева) и большими (справа) элементами.

## Сложность

**Время** (дополнения из исходного конспекта):
* **Лучший случай — $O(n \log n)$:** каждый выбор `pivot` делит подмассив на две равные части.
* **Средний случай — $O(n \log n)$:** математическое ожидание на случайных данных.
* **Худший случай — $O(n^2)$:** статический выбор крайнего элемента как `pivot` на уже отсортированном или обратно отсортированном массиве.

**Память:**
* Partition — $O(1)$ (только локальные переменные `i`, `j`).
* Стек рекурсии: в среднем глубина $O(\log n)$ $\implies$ $O(\log n)$ памяти; в худшем случае (разбиения на $n, n-1, n-2, \dots$) — $O(n)$.
* Подробное математическое доказательство — в учебнике Кормена (отсылка из лекции).

**Устойчивость:** нет.

## Способы предотвращения худшего случая

1. **Рандомизированный выбор (Randomized QuickSort):** выбрать случайный индекс $k \in [l, r]$ и выполнить `swap(a[k], a[r])` перед `partition`. Даёт $O(n \log n)$ в среднем независимо от порядка входных данных.
2. **Медиана трёх (Median-of-Three):** pivot — медиана первого, среднего и последнего элементов: $\text{median}(a[l],\ a[(l+r)/2],\ a[r])$.

## Практические оптимизации

* **Устранение хвостовой рекурсии:** рекурсивный вызов только для меньшего подмассива, для большего — переход к следующей итерации цикла. Гарантирует глубину стека $O(\log n)$.
* **Порог для сортировки вставками:** для маленьких подмассивов ($n \le 16$) эффективнее Insertion Sort.
* **Интроспективная сортировка (IntroSort):** начинает с QuickSort, а если глубина рекурсии превышает $2 \log n$ — переключается на **HeapSort**, предотвращая худший случай $O(n^2)$.

# 9. Двоичная куча и пирамидальная сортировка (HeapSort)

## Определения

* **Двоичная куча (пирамида, Heap)** — **завершённое бинарное дерево**: все уровни, кроме последнего, заполнены полностью, последний заполняется слева направо.
* **Max-Heap:** значение в любой вершине не меньше значений её детей: $A[k] \ge A[2k+1]$ и $A[k] \ge A[2k+2]$. В корне $A[0]$ — максимум.
* **Min-Heap:** значение в любой вершине не больше значений её детей.

## Формулы: представление в массиве

Куча хранится прямо в массиве без указателей и «пустых мест»:

| Что | Индекс |
| :--- | :--- |
| Корень | `0` |
| Левый сын узла `i` | `2 * i + 1` |
| Правый сын узла `i` | `2 * i + 2` |
| Родитель узла `i` | `(i - 1) / 2` (округление вниз) |

Все формулы вычисляются за $O(1)$.

## Методы и алгоритмы: операции с кучей

* **Просеивание вниз (`siftDown` / `heapify`).** Применяется, когда свойство кучи нарушено только в узле `i`, а его левое и правое поддеревья — корректные пирамиды. Узел `i` сравнивается с наибольшим из детей `j`; если $A[i] < A[j]$ — `swap(A[i], A[j])` и просеивание продолжается от `j`.
  *Сложность:* $O(\log n)$ по времени; итеративная версия — $O(1)$ доп. памяти, рекурсивная — $O(\log n)$ (стек).
* **Просеивание вверх (`siftUp`).** При добавлении элемента в конец кучи он поднимается вверх, пока больше своего родителя `(i - 1) / 2`. *Сложность:* $O(\log n)$.
* **Вставка (`insert`).** `heapSize++`, `A[heapSize - 1] = key`, затем `siftUp(heapSize - 1)`. *Сложность:* $O(\log n)$.
* **Удаление произвольного элемента (`delete(i)`) / извлечение максимума.** `A[i]` меняется местами с последним элементом `A[heapSize - 1]`, `heapSize--`, затем к новому элементу на позиции `i` применяется `siftDown` или `siftUp`. При удалении корня — `swap` с последним и `siftDown(A, 0, heapSize)`. *Сложность:* $O(\log n)$.
* **Построение кучи (`buildHeap`).** Вызов `siftDown` для всех узлов, имеющих детей, от $i = n/2 - 1$ до $0$. *Сложность:* **$O(n)$** (суммарная высота просеивания по всему дереву даёт линейное время).

## Алгоритм HeapSort

**Идея:** HeapSort — эволюция сортировки выбором. Вместо линейного поиска максимума за $O(n)$ элементы организуются в Max-Heap, из которой максимум извлекается за $O(\log n)$ (аналогия с турнирной сеткой / кубком).

```cpp
#include <vector>
#include <algorithm>

// Итеративное просеивание вниз — O(1) дополнительной памяти
void siftDown(std::vector<int>& A, int i, int heapSize) {
    while (2 * i + 1 < heapSize) {
        int left = 2 * i + 1;
        int right = 2 * i + 2;
        int j = left;

        // Находим наибольшего из детей
        if (right < heapSize && A[right] > A[left]) {
            j = right;
        }
        // Если текущий элемент >= наибольшего ребёнка — завершаем
        if (A[i] >= A[j]) {
            break;
        }
        std::swap(A[i], A[j]);
        i = j; // спускаемся на следующий уровень
    }
}

// Построение кучи за O(n)
void buildHeap(std::vector<int>& A) {
    int n = A.size();
    for (int i = n / 2 - 1; i >= 0; i--) {
        siftDown(A, i, n);
    }
}

void heapSort(std::vector<int>& A) {
    int n = A.size();
    buildHeap(A);                          // Фаза 1: построение Max-Heap

    int heapSize = n;
    for (int i = 0; i < n - 1; i++) {      // Фаза 2: извлечение максимумов
        std::swap(A[0], A[heapSize - 1]);  // корень (максимум) — в конец
        heapSize--;                        // исключаем его из кучи
        siftDown(A, 0, heapSize);          // восстанавливаем свойство кучи
    }
}
```

## Сложность и свойства HeapSort

* **Время (любой случай):** $O(n \log n)$ — построение кучи $O(n)$, затем $n-1$ вызовов `siftDown` по $O(\log n)$.
* **Память:** $O(1)$ при итеративном `siftDown` (in-place).
* **Устойчивость:** нет.
* **Практическое замечание:** на небольших массивах ($N \le 1000$) сортировка вставками примерно вдвое быстрее HeapSort из-за меньшей константы и хорошей локальности данных в кэше.
* HeapSort улучшает сортировку выбором с $O(n^2)$ до $O(n \log n)$ и работает за $O(1)$ доп. памяти во всех случаях.
