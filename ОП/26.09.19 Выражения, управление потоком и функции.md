# Расширенный конспект лекции: Базовые конструкции C++

---

## 1. Выражения, инструкции и блоки (Expressions, Statements, Blocks)

### 1.1. Выражения (Expressions)
**Выражение** — это синтаксическая конструкция, которая вычисляет некоторое значение и/или порождает побочный эффект (изменение состояния программы).

* **Значение выражения:** каждое выражение в C++ обладает типом и категорией значения (например, *lvalue* — объект с именем и адресом в памяти, *rvalue* — временное значение).
* **Побочный эффект (Side Effect):** модификация состояния памяти или выполнение операций ввода-вывода.
  * Пример: `a + b` — чистое вычисление без побочных эффектов.
  * Пример: `i++` (постфиксный инкремент) вычисляет старое значение переменной `i`, но параллельно инициирует побочный эффект: увеличение `i` на `1`.
* **Выражения типа `void`:** существуют выражения, не возвращающие значения (например, вызов функции `void func()`). Их нельзя присвоить переменной или использовать внутри других вычислений.

### 1.2. Инструкции (Statements)
**Инструкция** — наименьшая автономная единица управления выполнением программы. Инструкция не имеет значения, она задаёт шаг действия.

* **Инструкция-выражение (Expression Statement):** получается добавлением `;` к любому выражению.
  ```cpp
  c = a + b; // Выражение присваивания стало инструкцией
  i++;       // Выражение инкремента стало инструкцией
  ;          // Пустая инструкция (null statement) — допустима синтаксисом
  ```
* **Управляющие инструкции (Selection & Iteration Statements):** `if`, `switch`, `while`, `for` и т. д. Они определяют порядок выполнения других инструкций.

### 1.3. Блоки и время жизни (Compound Statements / Blocks)
**Блок (составная инструкция)** — последовательность инструкций, заключённая в фигурные скобки `{ ... }`.

* С точки зрения синтаксиса блок рассматривается компилятором как **одна составная инструкция**.
* Блок создаёт **локальную область видимости (block scope)**.
* **Автоматическое управление памятью (RAII):** переменные, объявленные внутри блока, создаются в момент объявления и уничтожаются при выходе потока управления из этого блока (память на стеке освобождается, вызываются деструкторы).

```cpp
{
    int temp = 42;
    std::cout << temp;
} 
// temp уничтожена, обращение к ней здесь вызовет ошибку компиляции
```

## 2. Ветвления и циклы

### 2.1. Условный оператор `if-else`

```cpp
if (condition) {
    // Ветка true
} else {
    // Ветка false
}
```

#### Неявное приведение к `bool`
Любое числовое значение в условии неявно приводится к типу `bool`:
* `0`, `0.0`, `nullptr` $\rightarrow$ `false`
* Любое ненулевое значение (включая отрицательные числа: `-1`, `42`) $\rightarrow$ `true`

#### Проблема «висячего else» (Dangling-Else Problem)
Синтаксис C++ допускает отсутствие фигурных скобок при единственной инструкции. Это приводит к синтаксической неоднозначности:

```cpp
// ПЛОХОЙ СТИЛЬ:
if (outer_condition)
    if (inner_condition)
        result = 1;
else
    result = 2; // К какому if относится этот else?
```

* **Правило компилятора:** ветвь `else` всегда связывается с **ближайшим предшествующим `if`**, у которого ещё нет `else`.
* В коде выше `else` привяжется к `if (inner_condition)`. Если `outer_condition == false`, весь блок будет пропущен, и `result` останется равным `0`.
* **Стандарт качества:** всегда оборачивать тело `if` и `else` в фигурные скобки `{}` независимо от количества строк.

#### Цепочки `else if`
Проверки идут последовательно сверху вниз. Выполняется **только первая ветвь**, условие которой оказалось истинным; остальные проверки пропускаются:

```cpp
if (score >= 90) {
    grade = 'A';
} else if (score >= 75) {
    grade = 'B';
} else {
    grade = 'F';
}
```

### 2.2. Циклы: `while`, `do-while`, `for`, Range-based `for`

#### 1. Цикл с предусловием (`while`)
Проверка условия происходит **до** выполнения тела. Если условие изначально ложно, цикл не выполнится ни разу.
```cpp
int n = 5;
while (n > 0) {
    --n;
}
```

#### 2. Цикл с постусловием (`do-while`)
Условие проверяется **после** выполнения тела цикла. Тело гарантированно выполнится хотя бы один раз.
```cpp
int x;
do {
    std::cin >> x;
} while (x < 0);
```

* **Идиома `do { ... } while (false);`**
  Используется для создания линейного блока кода с возможностью безопасного досрочного выхода без использования `goto`:
  ```cpp
  do {
      if (!step1_ok()) break; // Выход из блока
      if (!step2_ok()) break; // Выход из блока
      // Критическая секция, выполняемая только если всё успешно
  } while (false);
  ```

#### 3. Классический цикл со счётчиком (`for`)
```cpp
for (initialization; condition; step) {
    statement;
}
```
* **Порядок выполнения:**
  1. `initialization` (выполняется 1 раз при входе).
  2. `condition` (проверяется перед каждой итерацией; если опущено, эквивалентно `true`).
  3. `statement` (тело цикла).
  4. `step` (выполняется строго **после** тела цикла).

#### 4. Range-based `for` (C++11)
Синтаксический сахар для последовательного перебора контейнеров и массивов:
```cpp
int arr[] = {1, 2, 3, 4};
for (int x : arr) {          // Копирование каждого элемента
    std::cout << x << ' ';
}
for (const auto& x : arr) {  // Передача по константной ссылке (без накладных расходов)
    std::cout << x << ' ';
}
```

### 2.3. Управление потоком выполнения: `break`, `continue` и тонкости `for`

* **`break`** — немедленно завершает работу самого вложенного цикла (`for`, `while`, `do-while`) или переключателя `switch`.
* **`continue`** — прерывает текущую итерацию и начинает следующую.

#### Разница поведения `continue` в `for` и `while`:
* В цикле `for` при вызове `continue` управление передаётся в блок **`step`** (`++i`), после чего проверяется `condition`.
* В наивной замене на `while`, если шаг инкремента помещён в конец тела, вызов `continue` приведёт к бесконечному зацикливанию:
  ```cpp
  // Зациклится при i == 1:
  int i = 0;
  while (i < 3) {
      if (i == 1) continue; // ++i будет пропущен!
      std::cout << i;
      ++i;
  }
  ```

#### Псевдо-оператор `-->` («идёт к» / goes-to)
В коде можно встретить конструкцию:
```cpp
int i = 5;
while (i --> 0) { // Читается как: while (i-- > 0)
    std::cout << i << ' '; // Вывод: 4 3 2 1 0
}
```
Это не отдельный оператор, а сочетание постфиксного декремента `i--` и оператора сравнения `>`. Значение `i` сравнивается с нулём, после чего уменьшается на 1.

### 2.4. Оператор множественного выбора `switch`

`switch` оптимизирует множественные проверки целочисленных констант (компилятор может построить *jump table* — таблицу прямых переходов по адресам, работающую за $O(1)$).

```cpp
switch (expression) {
    case CONST_1:
        // код
        break; // Обязателен, чтобы не провалиться в CONST_2
    case CONST_2:
    case CONST_3: // Группировка: код выполнится для 2 и 3
        handle_2_or_3();
        break;
    default: // Выполняется, если совпадений не найдено
        handle_default();
        break;
}
```

* **Ограничения:** 
  * `expression` должно иметь целочисленный тип (`int`, `char`, `short`, `long`) или тип перечисления (`enum`). Нельзя использовать строки `std::string` или числа с плавающей точкой `double`.
  * Метки `case` обязаны быть константами времени компиляции (*constant expressions*).
* **Сквозное выполнение (Fallthrough):** если в конце `case` не поставить `break`, выполнение перейдёт к следующей метке `case` независимо от условий.
* **Инициализация внутри `switch`:** объявление переменных с инициализацией внутри блока `switch` запрещено перескакивать через метки `case` (вызовет ошибку компиляции `crosses initialization`).

## 3. Функции и рекурсия

### 3.1. Объявление vs Определение

* **Объявление (Declaration / Прототип):** сообщает компилятору имя функции, типы принимаемых аргументов и возвращаемый тип (сигнатуру). Позволяет вызывать функцию до её фактической реализации.
  ```cpp
  int calculate_sum(int a, int b); // Объявление
  ```
* **Определение (Definition):** содержит сигнатуру и фактическое тело функции `{ ... }`. Должно существовать в одном экземпляре (согласно правилу ODR — *One Definition Rule*).
  ```cpp
  int calculate_sum(int a, int b) { // Определение
      return a + b;
  }
  ```

### 3.2. Возврат значений и тип `void`
* Оператор `return expression;` немедленно завершает выполнение функции и передаёт результат в точку вызова.
* Тип `expression` должен неявно приводиться к заявленному возвращаемому типу.
* Если тип возврата `void`, инструкция `return;` (без значения) опциональна в конце функции и используется только для досрочного выхода.

---

### 3.3. Функция `main` и аргументы командной строки

Функция `main` — точка входа в программу.

#### Сигнатуры:
1. `int main()` — без аргументов.
2. `int main(int argc, char* argv[])` (или `char** argv`) — с параметрами командной строки.

#### Свойства:
* Достижение конца `main` без явного `return` компилятор автоматически интерпретирует как `return 0;` (код успешного завершения `EXIT_SUCCESS`).
* `argc` (*argument count*) — количество переданных аргументов. Всегда $\ge 1$ в штатных ситуациях.
* `argv` (*argument vector*) — массив указателей на нуль-терминированные строки (`C-strings`).
  * `argv[0]` — имя/путь к исполняемому файлу программы.
  * `argv[1]` ... `argv[argc - 1]` — переданные аргументы.
  * `argv[argc]` гарантированно равен `nullptr`.

### 3.4. Рекурсия и организация памяти (Call Stack)

**Рекурсивная функция** — функция, которая прямо или косвенно вызывает саму себя.

#### Необходимые условия корректной рекурсии:
1. **Базовый случай (Base Case / Терминальное условие):** условие выхода, при котором рекурсивные вызовы прекращаются.
2. **Шаг рекурсии:** вызов функции с параметрами, приближающими вычисление к базовому случаю.

#### Механизм работы:
При каждом вызове функции в области памяти **Стек (Call Stack)** выделяется **стековый кадр (Stack Frame)**:
* Сохраняются аргументы функции.
* Сохраняются локальные переменные.
* Сохраняется адрес возврата (адрес инструкции, куда нужно вернуться после завершения функции).

```cpp
// Пример: рекурсивный факториал
unsigned long long factorial(unsigned int n) {
    if (n == 0) return 1;          // 1. Базовый случай
    return n * factorial(n - 1);    // 2. Шаг рекурсии
}
```

#### Сравнение: Рекурсия vs Итерация

| Характеристика | Рекурсия | Итерация (Цикл) |
| :--- | :--- | :--- |
| **Память** | $O(N)$ — требует память стека под каждый вызов. | $O(1)$ — использует фиксированное число переменных. |
| **Быстродействие** | Накладные расходы на вызовы функций и передачу контекста. | Максимальная скорость работы на уровне процессора. |
| **Риски** | **Переполнение стека (Stack Overflow)** при большой глубине. | Зацикливание (Infinite Loop) при ошибке в условии. |
| **Читаемость** | Часто элегантнее для древовидных и рекурсивных структур. | Лучше подходит для линейных последовательностей. |

#### Переполнение типов (Integer Overflow)
* Для беззнаковых типов (`unsigned int`, `unsigned long long`): переполнение не является ошибкой и определено стандартом как **арифметика по модулю $2^N$** (где $N$ — число бит типа). Результат просто «оборачивается» вокруг нуля.
* Для знаковых типов (`int`, `long long`): переполнение является **неопределённым поведением (Undefined Behavior)**.

## 4. Области видимости и сокрытие имён (Shadowing)

### 4.1. Виды областей видимости
1. **Глобальная область (Global/File scope):** сущности объявлены вне любых функций/классов, видны во всём файле.
2. **Область видимости блока (Block/Local scope):** ограничена фигурными скобками `{ ... }`.
3. **Область видимости параметров функции:** аргументы видны во всём теле функции.

### 4.2. Механизм сокрытия имён (Name Shadowing)
Если во внутренней области видимости объявляется идентификатор с тем же именем, что и во внешней, **внутреннее имя полностью скрывает внешнее** до конца текущего блока.

```cpp
#include <iostream>

int value = 100; // 1. Глобальная переменная

void demo(int value) { // 2. Параметр скрывает глобальную переменную value
    std::cout << "Параметр: " << value << '\n';
    
    {
        double value = 3.14; // 3. Локальная переменная скрывает параметр value
        std::cout << "Локальная в блоке: " << value << '\n';
        
        // Доступ к глобальной переменной через оператор разрешения области видимости (::)
        std::cout << "Глобальная: " << ::value << '\n';
    }
}

int main() {
    demo(42);
    return 0;
}
```

### 4.3. Практические следствия сокрытия имён
* **Ошибки сопровождения кода:** разработчик может непреднамеренно изменить локальную переменную, предполагая, что работает с внешней.
* **Рекомендация:** включать предупреждения компилятора (`-Wshadow` в GCC/Clang) и избегать перекрытия имён переменных во вложенных областях видимости.
