# Полный конспект: Указатели, адресация, массивы и модель памяти C++

## 1. Архитектура памяти и понятие указателя

### 1.1. Модель плоской памяти (Flat Memory Model)
Память программы представляется как непрерывный массив байтов, где каждый байт имеет свой порядковый номер — **адрес**.

```
[ Байт 0 ] [ Байт 1 ] ... [ Байт 0x1000 ] [ Байт 0x1001 ] ...
   ^
 Адрес
```

* **Объект в памяти**: Последовательность из одного или нескольких байтов.
* **Адрес объекта**: Адрес его самого **первого (младшего) байта**.
* **Размер объекта**: `sizeof(T)` возвращает количество байт, занимаемых объектом.

### 1.2. Сегменты виртуальной памяти процесса
Когда ОС загружает программу в память, виртуальное адресное пространство делится на сегменты:
1. **Текст / Код (`.text`)**: Инструкции процессора (только для чтения). Сюда указывают указатели на функции.
2. **Сегмент данных (`.data` / `.rodata` / `.bss`)**:
   * `.rodata` — константы (строковые литералы `"Hello"`, константные глобальные переменные). Попытка записи вызывает ошибку сегментации (`Segmentation Fault`).
   * `.data` — инициализированные глобальные и статические переменные.
   * `.bss` — неинициализированные глобальные и статические переменные (заполняются нулями при старте).
3. **Куча (Heap)**: Динамическая память (`malloc` / `free`, `new` / `delete`). Растет «снизу вверх» (к старшим адресам).
4. **Стек (Stack)**: Локальные переменные, кадры вызова функций, адреса возврата. Растет «сверху вниз» (к младшим адресам на большинстве архитектур).

## 2. Анатомия указателя

Указатель — это самостоятельная переменная, значением которой является числовой адрес другой области памяти или `nullptr`.

### 2.1. Размер указателя
Размер указателя зависит от целевой архитектуры процессора и модели данных ABI, а не от типа данных, на который он указывает:
* **32-битные архитектуры (x86, ARM32 / ILP32)**: `sizeof(T*) == 4` байта (32 бита).
* **64-битные архитектуры (x86-64, AArch64 / LP64 или LLP64)**: `sizeof(T*) == 8` байт (64 бита).

> **Исключение:** Размеры указателей на функции-члены классов (`void (MyClass::*)()`) могут быть **16 или 32 байта**, так как им необходимо учитывать множественное и виртуальное наследование (хранить смещение `this-adjustment` и смещение в vtable).

```cpp
#include <iostream>

struct BigStruct {
    char data[1024 * 1024]; // 1 Мб
};

int main() {
    char* cp = nullptr;
    BigStruct* sp = nullptr;

    // Оба выведут 8 на 64-битной системе
    std::cout << sizeof(cp) << ' ' << sizeof(sp) << '\n';
}
```

## 3. Операторы `&`, `*` и уровни косвенности

* `&x` — **взятие адреса** (Address-of operator): возвращает временный указатель (`rvalue`) на объект `x`.
* `*p` — **разыменование** (Indirection / Dereference operator): возвращает lvalue-ссылку на объект по адресу `p`.

```cpp
int a = 42;
int* p = &a;       // p хранит адрес a
int** pp = &p;     // pp хранит адрес указателя p
int*** ppp = &pp;  // ppp хранит адрес указателя pp

***ppp = 100;      // Эквивалентно: a = 100;
```

### Память при тройном указателе:
```
 Переменная:      a            p            pp           ppp
 Адрес:        0x1000       0x2000        0x3000        0x4000
 Значение:    [  100  ] <─ [ 0x1000 ] <─ [ 0x2000 ] <─ [ 0x3000 ]
```

## 4. Глубокий разбор `const` с указателями

Порядок чтения определений сложных типов — **справа налево (Clockwise/Spiral Rule)**.

```cpp
int x = 10, y = 20;

// 1. Указатель на константу (Pointer to constant)
// Читаем: p1 — это указатель (*) на константный (const) int.
const int* p1 = &x; 
int const* p1_alt = &x; // Полный эквивалент
// *p1 = 15;            // ОШИБКА: данные защищены от записи
p1 = &y;                // ОК: сам указатель можно перенаправить

// 2. Константный указатель (Constant pointer)
// Читаем: p2 — это константный (const) указатель (*) на int.
int* const p2 = &x;
*p2 = 15;               // ОК: данные менять можно
// p2 = &y;             // ОШИБКА: адрес зафиксирован навечно

// 3. Константный указатель на константу
// Читаем: p3 — это константный (const) указатель (*) на константный (const) int.
const int* const p3 = &x;
// *p3 = 15;            // ОШИБКА
// p3 = &y;             // ОШИБКА
```

### Практическое правило:
* Если `const` стоит **слева** от звездочки `*` — защищены **данные**.
* Если `const` стоит **справа** от звездочки `*` — защищен **сам указатель** (адрес).

## 5. Нулевые указатели: `nullptr` против `NULL` и `0`

### Историческая проблема `NULL`
В стандарте C `NULL` определялся как `((void*)0)`. В C++ такое определение невозможно без явного приведения типов, поэтому `NULL` определили как целочисленный литерал `0` или `0L`. Это создавало критическую неоднозначность при перегрузках:

```cpp
void log(int code);
void log(void* ptr);

log(0);    // Вызовет log(int)
log(NULL); // Зависит от реализации: часто вызывает log(int) вместо log(void*)!
```

### `std::nullptr_t` (начиная с C++11)
`nullptr` — это ключевое слово и литерал типа `std::nullptr_t`. 
* Он неявно приводится к любому типу указателя на объект или функцию.
* Он неявно приводится к `bool` (значение `false`).
* Он **не приводится** к целочисленным типам (`int`, `long`).

```cpp
log(nullptr); // Однозначно вызовет log(void*)
```

## 6. Жизненный цикл памяти, Dangling Pointers и UB

### 6.1. Висячие указатели (Dangling Pointers)
Указатель, хранящий адрес области памяти, которая была освобождена или вышла из области видимости.

```cpp
int* CreateBadPointer() {
    int local_variable = 100; 
    return &local_variable; // ОШИБКА: local_variable уничтожается при выходе из функции!
} // Стек очищается (деаллоцируется кадр функции)

void CrashExample() {
    int* ptr = CreateBadPointer(); // ptr — висячий указатель (Dangling)
    // Любое чтение/запись *ptr — Undefined Behavior (UB)
}
```

### 6.2. «Дикие» (Wild) указатели
Указатель, который не был инициализирован при создании. Он хранит «мусорный» адрес памяти, оставшийся на стеке:

```cpp
int* wild_ptr; // Не инициализирован!
// *wild_ptr = 5; // Гарантированный сбой программы или порча чужих данных в памяти
```

### 6.3. Виды Undefined Behavior при работе с указателями
1. Разыменование `nullptr`.
2. Разыменование неинициализированного указателя.
3. Разыменование висячего указателя.
4. Выход за границы массива при адресной арифметике (разыменование `arr + N`).
5. Нарушение правил строгого алиасинга (Strict Aliasing Rule).
6. Разыменование указателя с нарушением выравнивания (Alignment).

## 7. Массивы, адресная арифметика и Array Decay

### 7.1. Физическая структура массива
Массив `T arr[N]` гарантированно располагается в памяти **единым монолитным блоком** без промежутков.

Адрес $i$-го элемента вычисляется аппаратно за 1 такт процессора по формуле:
$$\text{Address}(arr[i]) = \text{BaseAddress}(arr) + i \times \text{sizeof}(T)$$

### 7.2. Array-to-Pointer Decay (Затухание массива)
В большинстве контекстов выражение типа «массив из $N$ элементов типа $T$» (`T[N]`) неявно преобразуется в «указатель на первый элемент типа $T$» (`T*`).

```cpp
int arr[5] = {10, 20, 30, 40, 50};
int* p = arr; // Decay: arr неявно превратился в &arr[0]
```

### Когда массив НЕ затухает (Исключения):
1. **`sizeof(arr)`**: Возвращает суммарный размер всех элементов (`5 * sizeof(int) = 20` байт).
2. **`&arr`**: Возвращает указатель на **весь массив**, тип которого `int (*)[5]`.
   * Шаг `arr + 1` сместит адрес на `sizeof(int)` (4 байта).
   * Шаг `(&arr) + 1` сместит адрес на `5 * sizeof(int)` (20 байт)!
3. **`decltype(arr)`**: Дает тип `int[5]`.
4. **Связывание по ссылке**: `int (&ref)[5] = arr;` (сохраняет точный размер).

### 7.3. Эквивалентность индексации и арифметики
Оператор `[]` в C++ — это синтаксический сахар для адресной арифметики:

$$a[b] \equiv *(a + b)$$

Из коммутативности сложения следует курьезный, но валидный факт стандарта:
```cpp
int arr[3] = {100, 200, 300};
std::cout << arr[1]; // 200
std::cout << *(arr + 1); // 200
std::cout << *(1 + arr); // 200
std::cout << 1[arr]; // 200 (полностью валидный C++)
```

### 7.4. Границы арифметики: Итераторный полуинтервал $[begin, end)$
Стандарт C++ разрешает вычислять указатель на элемент, находящийся **сразу за последним** (`arr + N`, так называемый `past-the-end pointer`), для использования в циклах, но **запрещает его разыменовывать**:

```cpp
int arr[3] = {1, 2, 3};
int* begin = arr;
int* end = arr + 3; // Валидный адрес границы

while (begin != end) {
    std::cout << *begin << '\n';
    ++begin;
}
// *end = 10; // UB! Разыменование границы запрещено.
// int* past_past = arr + 4; // UB! Выход за пределы границы даже без разыменования!
```

## 8. C-строки, строковые литералы и память

### 8.1. Внутреннее устройство
C-строка (null-terminated string) — это массив `char`, в конце которого стоит байт со значением `0` (`'\0'`).

```
Символы: [ 'H' ] [ 'e' ] [ 'l' ] [ 'l' ] [ 'o' ] [ '\0' ]
Байты:    0x48    0x65    0x6C    0x6C    0x6F    0x00
Индексы:    0       1       2       3       4       5
```

### 8.2. Литерал против Массива
```cpp
// 1. Строковый литерал
const char* str = "Hello"; 
// Память выделена в секции .rodata (только для чтения). 
// str[0] = 'h'; // Segmentation Fault (UB)

// 2. Инициализация массива символов
char arr[] = "Hello"; 
// Компилятор создает массив в стеке размером 6 байт и копирует туда "Hello\0".
arr[0] = 'h'; // ОК: модифицируется локальный стек
```

## 9. Низкоуровневые механизмы: `void*`, выравнивание и порядок байтов

### 9.1. Универсальный указатель `void*`
`void*` представляет собой «сырой» адрес без типа.
* У него отсутствует размер (`sizeof(void)` не определен стандартом).
* К нему нельзя применить разыменование (`*ptr` — ошибка).
* К нему нельзя применить адресную арифметику (`ptr + 1` — ошибка в стандартном C++).

```cpp
double pi = 3.14159;
void* raw = &pi;

// Восстановление типа через static_cast:
double* typed = static_cast<double*>(raw);
std::cout << *typed << '\n';
```

### 9.2. Порядок байтов (Endianness)
Число `0x12345678` (4 байта) распределяется по адресам памяти по-разному в зависимости от архитектуры:

```
Адрес в памяти:    0x00     0x01     0x02     0x03
--------------------------------------------------
Little-Endian:     0x78     0x56     0x34     0x12  (Младший байт по младшему адресу: x86, ARM)
Big-Endian:        0x12     0x34     0x56     0x78  (Старший байт по младшему адресу: Сеть, IBM)
```

**Проверка Endianness в C++20:**
```cpp
#include <bit>
#include <iostream>

int main() {
    if constexpr (std::endian::native == std::endian::little) {
        std::cout << "Архитектура Little-Endian\n";
    } else if constexpr (std::endian::native == std::endian::big) {
        std::cout << "Архитектура Big-Endian\n";
    }
}
```

### 9.3. Выравнивание данных (Alignment)
Процессорам неэффективно (а на некоторых RISC-процессорах запрещено на аппаратном уровне) читать данные по произвольным адресам. 
* 4-байтный `int` должен иметь адрес, кратный 4.
* 8-байтный `double` / `int64_t` должен иметь адрес, кратный 8.

```cpp
struct BadAlignment {
    char a;     // 1 байт
    // 3 байта padding (пустое заполнение компилятором для выравнивания)
    int b;      // 4 байта
    char c;     // 1 байт
    // 3 байта padding
}; // Итоговый sizeof: 12 байт!

struct GoodAlignment {
    int b;      // 4 байта
    char a;     // 1 байт
    char c;     // 1 байт
    // 2 байта padding
}; // Итоговый sizeof: 8 байт!
```

## 10. Указатели на функции и Function Decaying

Функции компилируются в бинарные инструкции и помещаются в сегмент памяти `.text`. Адрес первой инструкции функции можно сохранить в указатель.

### 10.1. Синтаксис объявления
```cpp
// Функция:
int Multiply(int a, int b) { return a * b; }

// Объявление указателя на функцию:
int (*func_ptr)(int, int) = Multiply; // или &Multiply

// Вызов функции через указатель:
int res1 = func_ptr(3, 4);   // Неявное разыменование
int res2 = (*func_ptr)(3, 4); // Явное разыменование (эквивалентно)
```

### 10.2. Разбор сложных сигнатур и `using`
Пример стандартной функции `signal` из `<csignal>`:
```cpp
// Традиционный C-синтаксис (сложно читается):
void (*signal(int sig, void (*handler)(int)))(int);

// Современный эквивалент на C++ через псевдонимы типов (type alias):
using SignalHandler = void (*)(int);

SignalHandler signal(int sig, SignalHandler handler);
```

## 11. Наглядная сравнительная матрица

| Операция / Тип | Синтаксис | Что константно? | Изменение адреса | Изменение объекта | Типичный размер (x64) |
| :--- | :--- | :--- | :---: | :---: | :---: |
| **Обычный указатель** | `T* p` | Ничего | Да | Да | 8 байт |
| **Указатель на константу** | `const T* p` | Объект | Да | **Нет** | 8 байт |
| **Константный указатель** | `T* const p` | Указатель | **Нет** | Да | 8 байт |
| **Константный на константу**| `const T* const p`| И объект, и указатель | **Нет** | **Нет** | 8 байт |
| **Сырой указатель** | `void* p` | — | Да | Нельзя разыменовать | 8 байт |
| **Массив** | `T arr[N]` | Адрес фиксирован | **Нет** | Да | $N \times \text{sizeof}(T)$ |
| **Указатель на функцию** | `R (*f)(Args...)`| Код функции неизменяем | Да | Только вызов | 8 байт |
