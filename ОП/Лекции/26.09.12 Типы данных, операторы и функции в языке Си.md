# ЧАСТЬ 1. Конспект лекции

## 1. Структура программы на C и функция `main`

Минимальная программа на C состоит из директив препроцессора, объявлений и главной функции:

```c
#include <stdio.h>

int main(void) {
    printf("Hello, World!\n");
    return 0; // 0 или EXIT_SUCCESS — успешное завершение программы
}
```

* **Сигнатуры `main`:**
  * `int main(void)` — программа не принимает аргументов командной строки.
  * `int main(int argc, char *argv[])` — программа принимает количество аргументов (`argc`) и массив строк (`argv`).
* **Точка входа:** Выполнение всегда начинается с функции `main`. В стандарте C99+ отсутствие явного `return 0;` в конце `main` автоматически возвращает `0`.

## 2. Базовые типы данных

Язык Си — статически типизированный язык со слабой типизацией (допускаются неявные приведения).

### 2.1. Целочисленные типы (`Integer types`)
Размер типов зависит от целевой архитектуры и компилятора, но стандарт гарантирует минимальные соотношения:
$$\text{sizeof(char)} \le \text{sizeof(short)} \le \text{sizeof(int)} \le \text{sizeof(long)} \le \text{sizeof(long long)}$$

| Тип | Модификаторы | Мин. гарантированный размер | Стандартный диапазон (на x86_64) |
| :--- | :--- | :--- | :--- |
| `char` | `signed`, `unsigned` | 1 байт (8 бит) | `signed`: $-128 \dots 127$<br>`unsigned`: $0 \dots 255$ |
| `short` | `signed`, `unsigned` | 2 байта (16 бит) | $-32\,768 \dots 32\,767$ |
| `int` | `signed`, `unsigned` | 2 байта (обычно 4) | $-2^{31} \dots 2^{31}-1$ |
| `long` | `signed`, `unsigned` | 4 байта (8 на Linux/macOS x86_64, 4 на Win x86_64) | $-2^{63} \dots 2^{63}-1$ (Linux 64-bit) |
| `long long` | `signed`, `unsigned` | 8 байт (64 бит) | $-2^{63} \dots 2^{63}-1$ |

> `char` по умолчанию может быть как `signed`, так и `unsigned` в зависимости от платформы/компилятора (на ARM часто `unsigned`, на x86 обычно `signed`).

### 2.2. Вещественные типы (`Floating-point types`)
Соответствуют стандарту IEEE 754:
* `float` — одинарная точность (4 байта, ~7 значащих десятичных цифр).
* `double` — двойная точность (8 байт, ~15–17 значащих цифр).
* `long double` — расширенная точность (80 бит на x86, либо 128 бит / 16 байт в зависимости от ABI).

### 2.3. Логический тип (`_Bool` / `bool`)
* До C99 логического типа не было (использовался `0` как `false`, ненулевое значение — `true`).
* Начиная с C99: встроенный тип `_Bool`, при подключении `#include <stdbool.h>` доступны псевдонимы `bool`, `true` (1) и `false` (0).
* В C23 `bool`, `true`, `false` стали ключевыми словами языка.

### 2.4. Тип `void`
Обозначает отсутствие значения или нетипизированную память:
* `void f(void)` — функция не принимает аргументов и ничего не возвращает.
* `void*` — указатель на нетипизированный адрес в памяти.

## 3. Литералы и константы

* **Целочисленные:**
  * Десятичные: `42`
  * Шестнадцатеричные (префикс `0x` / `0X`): `0x2A`
  * Восьмеричные (префикс `0`): `052` *(осторожно: ведущий ноль меняет систему счисления!)*
  * Двоичные (C23): `0b00101010`
  * Суффиксы: `U` (unsigned), `L` (long), `LL` (long long) — например, `42ULL`.
* **С плавающей точкой:**
  * `3.14` (тип `double`), `3.14f` / `3.14F` (тип `float`), `3.14L` (тип `long double`).
  * Экспоненциальная запись: `1.5e-3` ($1.5 \times 10^{-3}$).
* **Символьные и строковые:**
  * `'A'` — целочисленный литерал типа `int` (значение ASCII 65).
  * `"Hello"` — строковый литерал (массив `const char[6]` с завершающим `\0`).

## 4. Операторы и выражения

### 4.1. Арифметические операторы
* Унарные: `+`, `-`
* Бинарные: `+`, `-`, `*`, `/`, `%`
* **Особенности целочисленного деления:** `7 / 2` дает `3` (дробная часть отбрасывается в сторону нуля).
* **Остаток от деления (`%`):** применяется **только** к целочисленным типам. Знак результата совпадает со знаком делимого (`-7 % 3 == -1`).

### 4.2. Инкремент и декремент
* **Префиксный (`++x`, `--x`):** изменяет значение переменной и возвращает *новое* значение.
* **Постфиксный (`x++`, `x--`):** возвращает *старое* значение, после чего переменная изменяется.

### 4.3. Операторы сравнения и логические операторы
* Сравнения: `==`, `!=`, `<`, `>`, `<=`, `>=`.
* Логические: `&&` (И), `||` (ИЛИ), `!` (НЕ).
* **Ленивые вычисления (Short-circuit evaluation):**
  * В `A && B`, если `A == false`, `B` **не вычисляется**.
  * В `A || B`, если `A == true`, `B` **не вычисляется**.

### 4.4. Побитовые операторы (Bitwise)
Работают только с целочисленными типами:
* `&` — побитовое И (AND)
* `|` — побитовое ИЛИ (OR)
* `^` — побитовое исключающее ИЛИ (XOR)
* `~` — побитовое НЕ (инверсия битов)
* `<<` — побитовый сдвиг влево ($x \ll n \equiv x \times 2^n$)
* `>>` — побитовый сдвиг вправо ($x \gg n \equiv x / 2^n$)

### 4.5. Тернарный условный оператор
`условие ? выражение_1 : выражение_2`
Если `условие` истинно, вычисляется и возвращается `выражение_1`, иначе — `выражение_2`.

### 4.6. Оператор `sizeof`
* Возвращает размер типа или объекта в байтах (тип возвращаемого значения — `size_t`).
* Вычисляется **на этапе компиляции** (исключение: VLA — массивы переменной длины).
* Пример: `sizeof(int)`, `sizeof(x)`.

## 5. Преобразования типов (Type Conversions)

1. **Integer Promotion (Целочисленное продвижение):**
   Все типы меньше `int` (`char`, `short`, `bool`) в арифметических выражениях автоматически повышаются до `int` (или `unsigned int`).
2. **Usual Arithmetic Conversions (Обычные арифметические преобразования):**
   При операциях над разными типами операнды приводятся к общему более «широкому» типу:
   $$\text{integer} \to \text{unsigned} \to \text{long} \to \text{float} \to \text{double} \to \text{long double}$$
3. **Явное приведение (Explicit Cast):**
   Синтаксис: `(тип)выражение`. Пример: `(double)a / b`.

## 6. Функции

### 6.1. Объявление (Прототип) vs Определение
```c
// Объявление (Function Declaration / Prototype)
// Сообщает компилятору сигнатуру функции до её использования
int add(int a, int b);

int main(void) {
    int sum = add(3, 4);
    return 0;
}

// Определение (Function Definition)
int add(int a, int b) {
    return a + b;
}
```

### 6.2. Передача аргументов
* В C все аргументы передаются **только по значению** (pass-by-value). Значения параметров копируются в стек вызываемой функции.
* Для изменения переменной из вызывающей функции необходимо передавать **указатель** (адрес) на эту переменную.

# ЧАСТЬ 2. Дополнения и важные нюансы (Gotchas & Best Practices)

## 1. Неопределенное поведение (Undefined Behavior — UB)

UB — ситуация, при которой стандарт языка не накладывает никаких ограничений на поведение программы. Компилятор вправе оптимизировать код, предполагая, что UB **никогда не произойдет**.

### Типичные примеры UB в операциях:
1. **Переполнение знакового целого (Signed Overflow):**
   ```c
   int x = INT_MAX;
   x = x + 1; // UB! (в отличие от unsigned, где гарантирован переход через 0)
   ```
   * *Примечание:* Для `unsigned int` переполнение строго определено стандартом как арифметика по модулю $2^n$ (wrap-around).

2. **Модификация переменной несколько раз без точки следования (Sequence Point):**
   ```c
   int i = 0;
   i = i++;           // UB!
   printf("%d %d\n", ++i, i++); // UB! (порядок вычисления аргументов функции не определен)
   ```

3. **Сдвиг на число бит, большее или равное ширине типа, либо сдвиг отрицательного числа:**
   ```c
   uint32_t a = 1;
   uint32_t b = a << 32; // UB! (для 32-битного числа допустим сдвиг 0..31)
   ```

4. **Деление на ноль / взятие остатка от нуля:**
   ```c
   int a = 5 / 0; // UB!
   ```

## 2. Ловушки приоритета операторов

Одна из самых частых ошибок в C — неправильная расстановка скобок из-за неочевидного приоритета:

| Выражение | Реальная трактовка компилятором | Ошибка / Что ожидал автор |
| :--- | :--- | :--- |
| `if (flags & MASK == 0)` | `if (flags & (MASK == 0))` | У `==` приоритет **выше**, чем у битового `&`. Всегда пишите `(flags & MASK) == 0`. |
| `*p++` | `*(p++)` | Сначала берется старое значение указателя, возвращается значение по нему, а указатель сдвигается вперед. |
| `*p.field` | `*(p.field)` | У `.` приоритет выше `*`. Для указателей на структуры используйте `p->field` или `(*p).field`. |
| `a << 1 + 1` | `a << (1 + 1)` | У сложения `+` приоритет **выше**, чем у битового сдвига `<<`. |

## 3. Фиксированные типы из `<stdint.h>` и `<inttypes.h>`

Поскольку размеры стандартных типов (`int`, `long`) варьируются в зависимости от компилятора и ОС, в промышленном коде рекомендуется использовать типы с гарантированной разрядностью (C99):

* `int8_t`, `int16_t`, `int32_t`, `int64_t` — знаковые целые точной ширины.
* `uint8_t`, `uint16_t`, `uint32_t`, `uint64_t` — беззнаковые целые точной ширины.
* `size_t` — беззнаковый тип для размеров объектов и индексации массивов (из `<stddef.h>`).
* `ptrdiff_t` — знаковый тип для разности указателей.

### Спецификаторы формата `printf`/`scanf` для вывода:
```c
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main(void) {
    uint64_t large_num = 10000000000ULL;
    size_t sz = sizeof(large_num);

    printf("Number: %" PRIu64 "\n", large_num); // PRIu64 из <inttypes.h>
    printf("Size: %zu\n", sz);                  // %zu для size_t
    return 0;
}
```

## 4. Особенности вещественных чисел (IEEE 754)

Вещественные числа в памяти представляются в виде $\text{знак} \cdot \text{мантисса} \cdot 2^{\text{порядок}}$ и не могут точно представить большинство десятичных дробей (например, $0.1$).

* **Никогда не сравнивайте `float` и `double` через `==`:**
  ```c
  double a = 0.1 + 0.2;
  if (a == 0.3) { /* Скорее всего НЕ выполнится! */ }
  ```
* **Правильное сравнение с учетом погрешности ($\varepsilon$):**
  ```c
  #include <math.h>
  #define EPS 1e-9

  if (fabs(a - 0.3) < EPS) {
      // Числа считаются равными
  }
  ```

## 5. Модификаторы типов (Qualifiers)

* `const` — переменная только для чтения (не может быть изменена после инициализации).
* `volatile` — запрещает компилятору оптимизировать доступ к переменной (используется для работы с железом/регистрами и многопоточностью/сигналами, так как значение может измениться извне программы).
* `static` (в контексте локальных переменных) — переменная сохраняет свое значение между вызовами функции и живет на протяжении всего времени работы программы.
* `inline` (в контексте функций) — подсказка компилятору подставить тело функции напрямую в место вызова вместо создания стекового кадра (для оптимизации микрофункций).

## Чек-лист для самопроверки перед лабораторными:
- [ ] Понимаю разницу между префиксным (`++x`) и постфиксным (`x++`) инкрементом.
- [ ] Помню, что деление `int / int` отсекает остаток, и для вещественного результата нужно хотя бы один операнд привести к `double` (`(double)a / b`).
- [ ] Оборачиваю битовые операции в скобки внутри логических условий: `(x & 1) == 0`.
- [ ] Помню, что переполнение `signed int` — это **UB**, а `unsigned int` — **модульная арифметика**.
- [ ] Проверяю правильность спецификаторов в `printf`/`scanf` (`%d` для `int`, `%f` для `float`, `%lf` для `double` в `scanf`, `%zu` для `size_t`).
