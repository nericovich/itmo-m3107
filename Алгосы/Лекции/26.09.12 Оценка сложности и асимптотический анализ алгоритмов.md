# Конспект: Оценка сложности и асимптотический анализ алгоритмов

---

## 1. Введение: Качество кода vs Качество алгоритма

* **Качество кода (Читабельность / Оформление):**
  * Влияет на команду и поддержку: если код сложный, неструктурированный и написан сплошным полотном («спагетти-код»), в нем тяжело искать ошибки и дорабатывать.
  * *Пользователь код не видит*, но видит результат его работы.
* **Качество алгоритма (Производительность):**
  * **Медленная работа:** пользователи уходят, бизнес теряет деньги. Мобильные устройства и рабочие машины часто ограничены по ресурсам.
  * **Чрезмерное потребление памяти:** нехватка RAM для других процессов, замедление системы, невозможность обрабатывать большие объемы данных.

---

## 2. Базовая оценка сложности: Память и Время

Сложность измеряется как функция от размера входных данных $n$:
* $M(n)$ — сложность по **памяти** (Memory).
* $T(n)$ — сложность по **времени** (Time).

### 2.1. Оценка памяти $M(n)$
* $1$ примитивная переменная = $1$ пункт сложности.
* Массив / строка размером $n$ = $n$ пунктов сложности.

### 2.2. Оценка времени $T(n)$
* $1$ базовая операция (присваивание, сравнение, арифметическое действие) = $1$ пункт сложности.
* Цикл из $n$ итераций по $k$ операций в каждой = $k \cdot n$ пунктов.
* Условие (`if`) с $t$ операциями (логические проверки + действия) = $t$ пунктов.

---

## 3. Примеры точного подсчета операций

### Пример 1: Циклы и условия
```c
int i, j, n = 100;              // M: +3; T: +1 (присваивание n)
int A[n] = 1;                   // M: +n; T: +n (инициализация)
char B[n];                      // M: +n

for i = 1 to n do               // T: +1 (старт цикла)
    j++;                        // T: +n (1 операция * n итераций)

i = n;                          // T: +1
while (A[i] + A[i-1] > 0) {     // T: условие (3 оп.)
    A[i + 1] = A[i];            // T: 2 оп.
    i = i - 1;                  // T: 2 оп.
    if (i < 0 && (i/2 == 0))    // T: 4 оп. (проверки)
        then j = n;             // T: 1 оп.
}                               // Итого в теле while: 3 + 2 + 2 + 5 = 12 оп. на итерацию
```
* **Память:** $M(n) = 3 + n + n = 2n + 3$
* **Время:** $T(n) = 1 + n + 1 + n + 1 + 12n = 14n + 2$

---

### Пример 2: Зависимый вложенный цикл (Арифметическая прогрессия)
```c
for i = 1 to n do
    for j = 1 to i do
        A[i] = A[i] + A[j];
```
Внутренний цикл зависит от шага внешнего цикла:
* Итерация $i = 1 \implies 1$ шаг
* Итерация $i = 2 \implies 2$ шага
* ...
* Итерация $i = n \implies n$ шагов

Общее число итераций находится через **сумму арифметической прогрессии**:
$$T(n) = \frac{1 + n}{2} \cdot n = \frac{n^2 + n}{2}$$

---

### Пример 3: Зависимость от входных данных (Лучший и худший случаи)
```c
i = N;
while (A[i] + A[i-1] > N) {
    A[i - 1] = A[i];
    i = i - 1;
}
```
* **Минимум (Лучший случай):** условие сразу ложно $\implies$ цикл не выполняется ни разу ($3$ операции на проверку условия).
* **Максимум (Худший случай):** цикл выполняется $N$ раз $\implies \approx 7N$ операций.

## 4. Асимптотический анализ сложности

При росте $n$ константы и младшие слагаемые теряют значимость. Анализируется **порядок роста** функции.

### Математические обозначения:

| Нотация | Название | Математическое определение | Смысл |
| :--- | :--- | :--- | :--- |
| **$O(g(n))$** | «О» большое (Big-O) | $\exists c > 0, n_0 > 0 : \forall n > n_0 \implies 0 \le f(n) \le c \cdot g(n)$ | **Оценка сверху** (худший случай) |
| **$\Omega(g(n))$** | Омега (Big-Omega) | $\exists c > 0, n_0 > 0 : \forall n > n_0 \implies 0 \le c \cdot g(n) \le f(n)$ | **Оценка снизу** (лучший случай) |
| **$\Theta(g(n))$** | Тета (Big-Theta) | $\exists c_1, c_2 > 0, n_0 > 0 : \forall n > n_0 \implies 0 \le c_2 g(n) \le f(n) \le c_1 g(n)$ | **Точная оценка** (сверху и снизу) |

> **Теорема о связи:** 
> $$f(n) = \Theta(g(n)) \iff f(n) = O(g(n)) \text{ и } f(n) = \Omega(g(n))$$

---

## 5. Свойства $O$-нотации

1. **Сумма:** $f_1(n) + f_2(n) = O(\max(g_1(n), g_2(n)))$ *(выбирается старший порядок роста)*.
2. **Произведение:** $f_1(n) \cdot f_2(n) = O(g_1(n) \cdot g_2(n))$.
3. **Умножение на константу:** $f_1(n) \cdot c = O(g_1(n))$ *(константа отбрасывается)*.
4. **Сложение с константой:** $f_1(n) + c = O(g_1(n))$ *(константа отбрасывается)*.

### Примеры упрощения:
* $T(n) = 2n^2 + 2n + 3 \implies O(n^2)$
* $T(n) = 1290n^3 + 12n^2 - 3586 \implies O(n^3)$
* $T(n) = 2n^2 \log n + 142n^2 - n \implies O(n^2 \log n)$
* $T(n) = 1290n^3 + 2n^2 \log n - 142n^2 - n + 386 \implies O(n^3)$

## 6. Зачем оценивать алгоритмы на практике?

### Сравнение двух подходов ($N = 10^7$ элементов):

* **Устройство 1 (Мощный сервер):** $10^9$ оп./сек, алгоритм $O(n^2)$:
  $$\text{Время} = \frac{10^7 \cdot 10^7}{10^9} = 10^5 \text{ сек} \approx 27.7 \text{ часов} \ (\mathbf{> \text{суток}})$$
* **Устройство 2 (Слабый смартфон):** $10^7$ оп./сек, алгоритм $O(n \log_2 n)$:
  $$\text{Время} = \frac{10^7 \cdot \log_2(10^7)}{10^7} \approx 23.25 \text{ сек} \ (\mathbf{< \text{минуты}})$$

> **Вывод:** Эффективный алгоритм на слабом оборудовании побеждает неэффективный алгоритм на мощном суперкомпьютере.

## 7. Классификация сложностей и типовые примеры

```
O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(n^3) < O(2^n) < O(n!)
[---------------- ОТЛИЧНО ----------------]   [---- ПЛОХО ----]   [-- КАТАСТРОФА --]
```

1. **Константная — $O(1)$:** доступ к элементу массива по индексу, базовые арифметические действия.
2. **Логарифмическая — $O(\log n)$:** 
   * Область поиска на каждом шаге делится на константу (например, пополам).
   * *Пример:* Бинарный поиск (`binSearch`).
3. **Линейная — $O(n)$:** 
   * Однократный проход по входным данным.
   * *Пример:* Поиск элемента/подсчет совпадений в массиве.
4. **Линеарифметическая — $O(n \log n)$:** 
   * Разделение задачи пополам ($\log n$) и объединение результатов проходом по всем элементам ($n$).
   * *Пример:* Сортировка слиянием (Merge Sort), Быстрая сортировка (Quick Sort в среднем).
5. **Квадратичная — $O(n^2)$:** 
   * Вложенные циклы, обработка всех пар элементов.
   * *Пример:* Сортировка пузырьком (Bubble Sort), простые вложенные циклы.
6. **Кубическая — $O(n^3)$:** 
   * Тройные вложенные циклы.
   * *Пример:* Перебор всех троек чисел в массиве, базовое умножение матриц.
7. **Экспоненциальная — $O(2^n)$ / $O(a^n)$:** 
   * Перебор всех подмножеств/комбинаций.
   * *Пример:* Перебор всех комбинаций занятых мест.
8. **Факториальная — $O(n!)$:** 
   * Наибольшая скорость роста, перебор всех перестановок.
   * *Пример:* Перебор всех перестановок людей на $n$ местах, задача коммивояжёра (полный перебор).

---

## 8. Практический ориентир применимости алгоритмов

| Сложность | Максимальный рабочий размер $n$ (при лимите времени $\approx 1$ сек) | Вердикт / Применение |
| :--- | :--- | :--- |
| $O(1)$ / $O(\log n)$ | Практически любые ($> 10^9$) | Работает всегда, везде и моментально |
| $O(n)$ | $n \approx 10^7 - 10^8$ | Отлично для потоковой обработки |
| $O(n \log n)$ | $n \approx 10^6 - 5 \cdot 10^7$ | Стандарт для эффективных сортировок |
| $O(n^2)$ | $n \approx 10^4$ | Терпимо только для небольших данных |
| $O(n^3)$ | $n \approx 500$ | Требует оптимизации |
| $O(2^n)$ | $n \approx 20 - 26$ | Очень медленно (экспоненциальный взрыв) |
| $O(n!)$ | $n \approx 10 - 11$ | Неприменимо для реальных объемов данных |
