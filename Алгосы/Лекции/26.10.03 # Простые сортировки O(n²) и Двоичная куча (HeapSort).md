# Конспект: Простые сортировки O(n²) и Двоичная куча (HeapSort)

Конспект охватывает классические элементарные алгоритмы сортировки — **сортировку вставками (Insertion Sort)**, **сортировку выбором (Selection Sort)**, **пузырьковую сортировку (Bubble Sort)**, а также структуру данных **двоичная куча (Max-Heap / Min-Heap)** и основанную на ней **пирамидальную сортировку (HeapSort)**.

---

## 1. Сортировка вставками (Insertion Sort)

### 1.1. Принцип работы
* **Разделение массива:** Массив разделяется на отсортированную часть (изначально состоит из одного элемента `A[0]`) и неотсортированную часть (`A[1...n-1]`).
* **Пошаговый процесс:** Начиная со второго элемента (`j = 1`), алгоритм берет текущий элемент (`key = A[j]`), ищет для него подходящую позицию в отсортированной части слева и вставляет его туда.
* **Оптимизация сдвигом вместо swap:** Вместо применения серии последовательных вызовов `swap(A[i], A[i+1])` (требующих 3 присваивания на каждый обмен), элементы отсортированной части, которые больше `key`, сдвигаются вправо на одну позицию (`A[i+1] = A[i]`). Затем `key` записывается в освободившееся место. Это сокращает число операций присваивания примерно в 3 раза.

### 1.2. Реализация на C++

```cpp
#include <iostream>
#include <vector>

void insertionSort(std::vector<int>& A) {
    int n = A.size();
    for (int j = 1; j < n; j++) {
        int key = A[j];        // Сохраняем вставляемый элемент
        int i = j - 1;         // Граница отсортированной части
        
        // Сдвигаем элементы, которые больше key, вправо
        while (i >= 0 && A[i] > key) {
            A[i + 1] = A[i];
            i = i - 1;
        }
        A[i + 1] = key;        // Вставляем key на нужную позицию
    }
}
```

### 1.3. Инвариант цикла
* **Формулировка:** В начале каждой итерации внешнего цикла `for` по индексу `j` подмассив `A[0...j-1]` состоит из элементов, изначально находившихся в `A[0...j-1]`, но расположенных в отсортированном порядке.
* **Инициализация:** При `j = 1` подмассив `A[0...0]` состоит из одного элемента и заведомо отсортирован.
* **Сохранение:** В теле цикла элементы `A[j-1], A[j-2]...`, большие `key`, сдвигаются вправо, сохраняя отсортированный порядок после вставки `key`.
* **Завершение:** По окончании цикла `j = n`, подмассив `A[0...n-1]` содержит все элементы исходного массива в отсортированном порядке.

### 1.4. Сложность и свойства
* **Временная сложность:**
  * **Худший случай:** $O(n^2)$ (массив отсортирован в обратном порядке; выполняется $\sum_{j=1}^{n-1} j = \frac{n(n-1)}{2}$ сравнений и сдвигов).
  * **Средний случай:** $O(n^2)$ (с меньшим коэффициентом постоянной благодаря эффективным сдвигам).
  * **Лучший случай:** $O(n)$ (исходный массив уже отсортирован; условие `while` ложно на первой же проверке).
* **Сложность по памяти:** $O(1)$ (требует постоянного объема дополнительной памяти для переменных `key`, `i`, `j`).
* **Устойчивость (Stability):** **Устойчивая** (элементы с равными ключами не меняют свой относительный порядок, так как условие сдвига строгое: `A[i] > key`).

## 2. Сортировка выбором (Selection Sort)

### 2.1. Принцип работы
* **Идея:** В неотсортированном подмассиве от `i` до `n-1` находится минимальный элемент.
* **Обмен:** Найденный минимум меняется местами с первым неотсортированным элементом `A[i]`.
* **Продвижение границы:** Индекс `i` увеличивается, и процесс повторяется для оставшейся неотсортированной части.
* **Связь с HeapSort:** Сортировка выбором тратит $O(n)$ времени на поиск минимума на каждом шаге ($n$ раз), что даёт $O(n^2)$. Замена линейного поиска минимума/максимума на извлечение из двоичной кучи (Max-Heap / Min-Heap) приводит к алгоритму пирамидальной сортировки (**HeapSort**) со сложностью $O(n \log n)$.

### 2.2. Реализация на C++

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

void selectionSort(std::vector<int>& A) {
    int n = A.size();
    for (int i = 0; i < n - 1; i++) {
        int minIndex = i; // Предполагаем, что текущий элемент минимальный
        
        // Ищем индекс минимального элемента в оставшейся части
        for (int j = i + 1; j < n; j++) {
            if (A[j] < A[minIndex]) {
                minIndex = j;
            }
        }
        
        // Меняем местами найденный минимум с A[i]
        if (minIndex != i) {
            std::swap(A[i], A[minIndex]);
        }
    }
}
```

### 2.3. Сложность и свойства
* **Временная сложность:**
  * **Худший, средний и лучший случаи:** **$O(n^2)$**. Число сравнений всегда фиксировано и равно $\frac{n(n-1)}{2}$, независимо от начальной упорядоченности данных.
* **Число обменов:** Выполняется ровно $O(n)$ операцией `swap` (не более $n-1$ обменов), что делает сортировку выбором полезной при высокой стоимости записи в память.
* **Сложность по памяти:** $O(1)$ дополнительной памяти.
* **Устойчивость (Stability):** **Неустойчивая** в стандартной реализации (далекий обмен `swap` может переместить элемент через одинаковые с ним значения).

## 3. Пузырьковая сортировка (Bubble Sort)

### 3.1. Принцип работы
* **Идея:** Алгоритм делает последовательные проходы по массиву, сравнивая соседние элементы `A[j]` и `A[j+1]`.
* **«Всплытие» элементов:** Если `A[j] > A[j+1]`, они меняются местами. За один полный проход наибольший элемент неотсортированной части «всплывает» на свою итоговую позицию в конце массива.
* **Оптимизация флагом `swapped`:** Если за весь проход по массиву не произошло ни одного обмена, массив уже отсортирован, и выполнение алгоритма можно досрочно завершить.

### 3.2. Реализация на C++

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

void bubbleSort(std::vector<int>& A) {
    int n = A.size();
    for (int i = 0; i < n - 1; i++) {
        bool swapped = false; // Флаг наличия обменов
        
        for (int j = 0; j < n - i - 1; j++) {
            if (A[j] > A[j + 1]) {
                std::swap(A[j], A[j + 1]);
                swapped = true;
            }
        }
        
        // Если обменов не было, массив отсортирован
        if (!swapped) {
            break;
        }
    }
}
```

### 3.3. Сложность и свойства
* **Временная сложность:**
  * **Худший случай:** $O(n^2)$ (массив отсортирован в обратном порядке).
  * **Средний случай:** $O(n^2)$.
  * **Лучший случай:** $O(n)$ (при использовании флага `swapped` для отсортированного массива выполняется $n-1$ сравнений и 0 обменов).
* **Сложность по памяти:** $O(1)$ дополнительной памяти.
* **Устойчивость (Stability):** **Устойчивая** (соседние элементы с равными ключами не меняются местами).

## 4. Двоичная куча (Пирамида) и пирамидальная сортировка (HeapSort)

### 4.1. Определение и свойства кучи
* **Структура:** Двоичная куча (пирамида / Heap) — это **завершённое бинарное дерево** (binary tree), у которого все уровни, кроме последнего, заполнены полностью, а последний уровень заполняется слева направо.
* **Основное свойство (Max-Heap):** Значение в любой вершине не меньше значений её дочерних узлов: $A[k] \ge A[2k+1]$ и $A[k] \ge A[2k+2]$. В корне $A[0]$ находится максимальный элемент.
* **Свойство (Min-Heap):** Значение в любой вершине не больше значений её дочерних узлов.
* **Представление в массиве:** Для хранения кучи не требуются динамические указатели — она хранится прямо в сортируемом массиве без "пустых мест":
  * Корень дерева: `A[0]`.
  * Левый сын узла `i`: `2 * i + 1`.
  * Правый сын узла `i`: `2 * i + 2`.
  * Родитель узла `i`: `(i - 1) / 2` (с округлением вниз).
  * Все формулы работают за $O(1)$ времени.

### 4.2. Основные операции с кучей
* **Просеивание вниз (`siftDown` / `heapify`):**
  * Применяется, когда свойство кучи нарушено только в текущем узле `i`, а его левое и правое поддеревья являются корректными пирамидами.
  * Узел `i` сравнивается с наибольшим из своих детей `j`. Если $A[i] < A[j]$, они меняются местами (`swap(A[i], A[j])`), и просеивание продолжается для узла `j`.
  * **Сложность:** $O(\log n)$ по времени. Итеративная версия требует $O(1)$ доп. памяти, а рекурсивная — $O(\log n)$ из-за стека рекурсии.
* **Просеивание вверх (`siftUp`):**
  * Применяется при добавлении элемента в конец кучи. Элемент поднимается вверх, пока он больше своего родителя `(i - 1) / 2`.
  * **Сложность:** $O(\log n)$ по времени.
* **Вставка элемента (`insert`):**
  * Размер кучи увеличивается на 1 (`heapSize++`), элемент записывается в конец (`A[heapSize - 1] = key`), после чего вызывается `siftUp(heapSize - 1)`.
  * **Сложность:** $O(\log n)$.
* **Удаление произвольного элемента (`delete(i)`) / извлечение максимума:**
  * Элемент `A[i]` меняется местами с последним элементом `A[heapSize - 1]`, размер кучи уменьшается (`heapSize--`).
  * Для восстановления свойства кучи к новому элементу на позиции `i` применяется просеивание (`siftDown` или `siftUp`).
  * При удалении корня (`A[0]`) он меняется местами с последним элементом и просеивается вниз (`siftDown(A, 0, heapSize)`).
  * **Сложность:** $O(\log n)$.
* **Эффективное построение кучи (`buildHeap`):**
  * Преобразование неотсортированного массива в Max-Heap выполняется вызовом `siftDown` для всех узлов, имеющих детей (от $i = n/2 - 1$ до $0$ с шагом -1).
  * **Сложность построения:** **$O(n)$** (суммарная высота просеивания по всему дереву дает линейное время).

### 4.3. Алгоритм HeapSort

#### Идея алгоритма:
HeapSort является эволюцией сортировки выбором. Вместо линейного поиска максимума за $O(n)$ на каждом шаге, элементы организуются в Max-Heap, позволяющую находить и извлекать максимум за $O(\log n)$ (аналогия с турнирной сеткой / кубком).

#### Код на C++:

```cpp
#include <iostream>
#include <vector>
#include <algorithm>

// Итеративное просеивание вниз (siftDown) — O(1) дополнительной памяти
void siftDown(std::vector<int>& A, int i, int heapSize) {
    while (2 * i + 1 < heapSize) {
        int left = 2 * i + 1;
        int right = 2 * i + 2;
        int j = left;
        
        // Находим наибольшего из дочерних узлов
        if (right < heapSize && A[right] > A[left]) {
            j = right;
        }
        
        // Если текущий элемент больше или равен наибольшему ребенку, завершаем
        if (A[i] >= A[j]) {
            break;
        }
        
        std::swap(A[i], A[j]);
        i = j; // Спускаемся на следующий уровень
    }
}

// Эффективное построение кучи за O(n)
void buildHeap(std::vector<int>& A) {
    int n = A.size();
    for (int i = n / 2 - 1; i >= 0; i--) {
        siftDown(A, i, n);
    }
}

// Главная функция пирамидальной сортировки (HeapSort)
void heapSort(std::vector<int>& A) {
    int n = A.size();
    
    // Фаза 1: Построение Max-Heap из неотсортированного массива
    buildHeap(A);
    
    int heapSize = n;
    // Фаза 2: Поочередное извлечение максимума в конец массива
    for (int i = 0; i < n - 1; i++) {
        std::swap(A[0], A[heapSize - 1]); // Перемещаем корень (максимум) в конец
        heapSize--;                        // Исключаем последний элемент из кучи
        siftDown(A, 0, heapSize);          // Восстанавливаем свойство кучи в корне
    }
}
```

### 4.4. Сложность и свойства HeapSort
* **Временная сложность:**
  * **Худший, средний и лучший случаи:** **$O(n \log n)$**. Построение кучи выполняется за $O(n)$, после чего производится $n-1$ шагов с вызовом `siftDown` за $O(\log n)$.
* **Сложность по памяти:** **$O(1)$** при итеративном `siftDown` (сортировка выполняется прямо в исходном массиве, in-place).
* **Устойчивость (Stability):** **Неустойчивая** (из-за "далеких" обменов элементов при `swap` корня с последним элементом и просеивании).
* **Практическое замечание:** На небольших массивах ($N \le 1000$) прямые вставки (Insertion Sort) оказываются примерно вдвое быстрее HeapSort из-за меньшей константы и хорошей локальности данных в кэше.

## 5. Сравнительный анализ алгоритмов

| Алгоритм | Время (Лучший) | Время (Средний) | Время (Худший) | Доп. память | Устойчивость | Число обменов |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **Сортировка вставками** | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Да | $O(n^2)$ (сдвигов) |
| **Сортировка выбором** | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Нет | $O(n)$ |
| **Пузырьковая сортировка** | $O(n)$ | $O(n^2)$ | $O(n^2)$ | $O(1)$ | Да | $O(n^2)$ |
| **Пирамидальная сортировка (HeapSort)** | $O(n \log n)$ | $O(n \log n)$ | $O(n \log n)$ | $O(1)$ | Нет | $O(n \log n)$ |

---

### Главные выводы:
1. **Сортировка вставками** — наиболее эффективная из элементарных сортировок на частично отсортированных данных или небольших массивах ($O(n)$ в лучшем случае).
2. **Сортировка выбором** минимизирует количество записей в память ($O(n)$ обменов), но делает $O(n^2)$ сравнений в любых условиях.
3. **Пузырьковая сортировка** с флагом `swapped` способна досрочно завершаться за $O(n)$, но обычно уступает вставкам из-за частых вызовов `swap`.
4. **Пирамидальная сортировка (HeapSort)** улучшает подход сортировки выбором с $O(n^2)$ до $O(n \log n)$, благодаря использованию структуры кучи для извлечения максимума за $O(\log n)$. Работает за $O(1)$ доп. памяти во всех случаях.
